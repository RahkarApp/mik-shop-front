# گزارش بازبینی مجدد شاپ‌ساز وب — ۲۲ اکتبر ۲۰۲۶

این فایل گزارش تکمیلی است و جای پنج مرجع رسمی پروژه را نمی‌گیرد. هیچ Backendی در این مرحله ویرایش نشده است.

## آنچه واقعاً بررسی شد

- بازخوانی قوانین، درخت فایل‌ها، Data Flow، Serviceهای REST، Routeها، Componentها، Checkout و قراردادهای Backend.
- کنترل معماری (`npm run check:architecture`)، تست‌های قراردادی (`npm run test:contract`) و بررسی مستقل ارجاع به نام‌های تعریف‌نشده با TypeScript parser/checker.
- تلاش برای نصب بسته‌ها و اجرای Build؛ نصب کامل وابستگی‌ها در این محیط به پایان نرسید. Build و تست مرورگر/سرور واقعی تأیید نشده‌اند.

## مرز انتشار

- Real هرگز به Demo مخفی fallback نمی‌کند. هیچ Socket وجود ندارد. یک قالب واحد حفظ شده است.
- قیمت، موجودی، مبلغ حمل، وضعیت پرداخت و محدوده فروشگاه باید از Backend و قرارداد تأییدشده برسد.
- بدون اجرای E2E واقعی خرید و Gateway، استفاده Production از مسیر Checkout تأیید نشده است.

## اصلاحات این نوبت

- کلید سبد شامل شناسه SKU (`proUID`) است؛ ذخیره سبد با مقدارهای غیرمعتبر فیلتر می‌شود.
- مبلغ نامشخص دیگر صفر/رایگان نمایش داده نمی‌شود؛ subtotal، shipping، discount، tax و total در Checkout فقط از Quote سرور خوانده می‌شوند.
- نمایش ارز از `store.currency`/`quote.currency` است و بدون واحد تأییدشده «واحد پول اعلام‌نشده» نمایش داده می‌شود.
- Quote در تغییر نشانی/سبد بی‌اعتبار می‌شود؛ تلاش مبهم ثبت سفارش بدون تکرار خودکار قفل می‌شود.
- قابلیت‌های اختیاری فقط با `true` واقعی فعال می‌شوند؛ دکمه مرجوعی/لغو سفارش به Flag مرتبط وابسته است.
- در Production، Proxy باید allowlist یا ingress معتبرسنج دامنه تأییدشده داشته باشد؛ `SHOP_TRUSTED_HOST_INGRESS=true` صرفاً با امنیت زیرساختی.
- Demo Quote شناسه/انقضا دارد و Order آزمایشی به Quote جاری گره خورده است.

- مسیر Next.js image optimizer برای URLهای CDN چندفروشگاهی غیرفعال شد تا درخواست سروری نامحدود به دامنه‌های خارجی مجاز نباشد. تصاویر همچنان مستقیم در مرورگر نمایش داده می‌شوند.

## وابستگی تیم بک‌اند

قرارداد `docs/BACKEND_CONNECTION_GUIDE_FA.md` و درخواست اصلاح `docs/BACKEND_CHANGE_REQUEST_FA.md` معتبرند. Config شامل `currency` از نوع `TOMAN|IRR` باید تحویل شود. `POST /checkout/orders` در Backend ارسالی وجود ندارد؛ مسیر `POST /order` برای سفارش واقعی نباید استفاده شود.
